셀프봇은 왜
"셀프봇"인가

// why a user token from a CLI counts as a self-bot

셀프봇을 규정하는 기술적 본질은 행동의 종류(읽기/쓰기)가 아니라, 공식 클라이언트 바깥에서 user token으로 자동화한다는 사실 그 자체다. "내 데이터만 읽는데?"에는 예외가 없다.

wss://gateway.discord.gg/?v=10&encoding=json
op 1→op 11
presence: online
공식·정상 경로 셀프봇·ToS 위반·탐지 위험 프로토콜·opcode documented 공식 문서 reverse-eng 커뮤니티 분석
01 — 토대

계정에는 두 종류가 있다 — Bot vs User

모든 논의는 토큰 한 줄에서 갈린다. Authorization 헤더가 어떻게 생겼느냐가 뒤따르는 탐지·ToS 이야기의 뿌리다.

02 — 아키텍처

Discord API는 두 개의 면을 가진다

하나는 Discord가 너에게 밀어주는 실시간 스트림(Gateway), 다른 하나는 네가 요청을 보내는 창구(REST). 이 분업을 잡아야 나머지가 말이 된다.

03 — 라이프사이클

공식 클라이언트는 어떻게 "항상 켜진" 연결을 세우나

앱을 켜면 즉시 일어나는 핸드셰이크. 이 시퀀스가 곧 "정상 클라이언트의 모습"이라는 기준선이다.

04 — 핵심 정밀 포인트

online을 유지하는 건 소켓이 아니라 ACK되는 heartbeat다

흔한 오해: "WebSocket이 열려 있으면 online." 정확히는 — 클라이언트가 op 1을 보내고 서버가 op 11로 응답(ACK)하는 박동이 살아 있어야 online이다. 박동을 보내도 ACK를 못 받으면 그 연결은 zombied 상태가 되고, presence는 offline으로 떨어진다.

아래에서 직접 끊어보라 — 오른쪽 버튼으로 ACK를 멈추면 패킷이 식고 presence가 죽는다.

왜 이게 탐지와 연결되나 공식 클라이언트는 이 박동 때문에 거의 항상 gateway 세션을 들고 있다. 우리의 REST-only CLI는 이 박동을 하지 않는다 → presence가 늘 offline이고, gateway 세션이 없다. 이 차이가 §6 탐지 신호의 물질적 근거가 된다.
05 — 지문

REST 호출 하나에 박힌 클라이언트 정체성

단 한 번의 요청에도 "내가 누구인지"가 촘촘히 적혀 나간다. 헤더에 마우스를 올려보라 — 어떤 건 documented, 어떤 건 reverse-eng이다.

06 — 탐지

클라이언트는 어떻게 지문으로 식별되는가

네 가지 신호가 흔히 거론된다. 하지만 신뢰도는 제각각이고, 하나는 오히려 거꾸로다.

⚠ 먼저 — 이건 추정이다 Discord는 탐지 내부를 공개하지 않는다. 아래는 community reverse-engineering 기반의 plausible / unverified 목록이지, 공식 확인이 아니다. 신호별 신뢰도를 차등해서 읽어야 한다.
07 — 위치잡기

우리의 정직한 CLI vs 위장형 셀프봇

네 CLI는 두 극단 사이에 있다. 정직한 CLI는 위장을 안 해서 헤더로 티가 나고, 위장형 셀프봇은 클라이언트를 흉내 내지만 더 깊은 지문에서 무너진다.

08 — 규범

무엇이 금지되고, 실제 단속은 어떤가

기술을 규범으로 착지시키자. 금지의 범위와 실제 enforcement는 분리해서 봐야 정직하다.

documented — 금지의 본질 "automating normal user accounts (self-bots) outside of the OAuth2/bot API is forbidden, and can result in account termination." Platform Manipulation Policy: "Modifying a user account to perform automated actions — regardless of the type of action." → read-only / 자기 데이터 예외 없음.

명시적으로 단속되는 타깃(documented): mass-DM 스패머, scraper, token seller/generator, raid·account-creation 도구, CAPTCHA-solving 서비스.

"조용한 개인 read-only 자동화는 실제로 거의 actioned되지 않는다"는 부분은 커뮤니티 관찰이지 보장이 아니다. escalation은 — 먼저 경고 ("Your account participated in … self-bots") → 지속 시 영구 ban, 극단적으로 server/IP ban. non-zero risk다.

09 — 합법적인 길

내 데이터는 Request Data로, 자동화는 Bot API로

① 내 데이터를 원한다
sanctioned self-data export

User Settings → Data & Privacy → Request Data (구버전 'Privacy & Safety', 모바일 'Request all of my data'). 결과는 메시지·서버·활동 JSON의 ZIP을 이메일 링크로 발송 — 보통 3–30일, 링크 30일 유효. 서버 전체 메시지 포함은 옵션 토글(기본 off).

② 자동화를 원한다
the only supported path

Bot API — Bot <token> + DiscordBot User-Agent + Gateway intents. 우리 toolkit의 discord-cli.js(봇)가 바로 이 길이다. discord-user-cli.js는 user token을 쓰므로 — 정의상 — 셀프봇 영역에 있다.

한 줄 정리 셀프봇 생태계는 "공식 클라이언트를 얼마나 정교하게 흉내 내느냐"의 군비 경쟁이다. 무언가를 빌드하려는 사람에게 옳고 안정적인 토대는 — 흉내가 아니라 — 문서화된 Bot 경로다.
