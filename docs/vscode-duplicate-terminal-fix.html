VS Code — Two PowerShells on Startup diagnosed & fixed 2026-07-01

Why the editor opened two PowerShell terminals on every launch (one/both flagged ⚠️) with annoying lag — the three independent causes, and the exact fix.

Root cause in one line: three independent mechanisms each open a terminal on startup — a startup-automation extension, VS Code's session restore, and VS Code's "show a terminal on startup" behavior. They don't know about each other, so you get duplicates.

Symptom

  • Every launch → two tabs both labelled powershell in the panel.
  • One (later both) showed a ⚠️ warning triangle on the tab.
  • Opening the terminal felt laggy at startup.
  • It opened a second PowerShell even when one already existed — clearly redundant.

The three independent terminal-openers (the core lesson)

The trap: no single setting was responsible. Three separate things each spawn a terminal, and turning off only one still leaves the others:

#MechanismWhat it doesWhere
1Auto Run Command extension (gabrielgrinberg.auto-run-command)Runs workbench.action.terminal.new on every startup ("condition":"always"). This is the deliberate "open a PowerShell + focus Explorer on launch" setup.auto-run-command.rules in settings.json
2Persistent sessionsterminal.integrated.enablePersistentSessions (default true) revives the previous session's terminals on reopen.VS Code default (was unset)
3Hide-on-startup behaviorterminal.integrated.hideOnStartup: "never" means "never hide the terminal on startup" → VS Code creates its own blank terminal to fill the panel when there's nothing to restore.settings.json
Why the first fix wasn't enough. Disabling only #2 (enablePersistentSessions:false) removed the restored terminal — but then #3 (hideOnStartup:"never") simply had VS Code spawn a fresh blank terminal in its place, so #1 + #3 still equalled two. You have to neutralize the overlap, not just one opener.

What each setting actually means

SettingMeaningValues
terminal.integrated.enablePersistentSessionsSave terminals (scrollback + process) on close and restore on reopentrue (default) / false
terminal.integrated.hideOnStartupWhether to hide (and thus not auto-create) the terminal view at startupnever · whenEmpty · always
terminal.integrated.persistentSessionScrollbackHow many lines are saved/restored across restarts (only when persistence is on)e.g. 250000 (250× the default 1000 — heavy)
terminal.integrated.scrollbackHow many lines are kept scrollable within a live sessione.g. 250000
auto-run-command.rulesCommands the Auto Run Command extension runs on startuparray of {condition, command}

The ⚠️ triangle, and the lag

The ⚠️ on a terminal tab = a revived persistent session whose process could not be reconnected (a stale/dead shell). When persistence was toggled off and the window was reloaded (not fully restarted), both old terminals were revived without live processes → both showed ⚠️. It's the tell-tale of "restored but dead."

The startup lag had three compounding sources, all firing at once at launch:

  • Two PowerShell spawns instead of one → the PowerShell $PROFILE loads twice.
  • persistentSessionScrollback: 250000 — restoring a quarter-million lines of scrollback on every launch is genuinely expensive.
  • The Clawd terminal-focus extension also spawns a hidden powershell.exe helper at startup (its getRaiseHelper()) — not a visible tab, but CPU at the worst moment.

The fix

Neutralize the overlap so only Auto Run Command (#1) opens a terminal:

// C:\Users\user\AppData\Roaming\Code\User\settings.json
"terminal.integrated.enablePersistentSessions": false,   // kill #2 (no restore) + kills the scrollback-restore lag
"terminal.integrated.hideOnStartup": "whenEmpty",        // kill #3 (don't auto-create when nothing to restore)
"auto-run-command.rules": [
  { "condition": "always", "command": "workbench.action.terminal.new" },  // #1 = the ONE terminal
  { "condition": "always", "command": "workbench.action.focusSideBar" }   // Explorer focus
]
Result: persistence restores nothing, VS Code doesn't spawn its own startup terminal, and Auto Run Command creates exactly one PowerShell + focuses Explorer. Faster too — one profile load, no 250k-line restore.

Gotchas & hard-won learnings

  • These settings only apply on a FULL restart — a "Reload Window" does not re-init persistence. Fully quit (Ctrl+Q / exit the app, no window left) and relaunch. A reload was why the first fix "didn't work" and left two ⚠️ ghosts.
  • Right settings file: Clawd-on-Desk shares C:\Users\user\AppData\Roaming\Code\User\settings.json — it has no separate user settings file. So edits there do apply to the Clawd editor. (Verified: it's the only settings.json holding auto-run-command.rules.)
  • Scrollback is two settings: scrollback governs the live session (kept), persistentSessionScrollback governs cross-restart restore (moot once persistence is off). 250000 is 250× default — worth trimming to ~20000 for memory.
  • "Fresh terminal on startup" and persistence are contradictory. If your workflow auto-opens a new terminal each launch (via Auto Run Command), you don't want restored terminals — turning persistence off aligns the two and removes the duplicate.
  • Method note: a multi-agent workflow was tried first but returned placeholder output; direct inspection of the actual settings.json found the real cause faster. When the answer lives in a handful of known files, read them.

How to verify

1. Close both ⚠️ terminals (trash icon on each tab). 2. FULLY quit VS Code / Clawd-on-Desk (Ctrl+Q — no window left). 3. Relaunch. Expect: exactly ONE fresh PowerShell + Explorer focused, no ⚠️. If still two -> a per-window double-fire of Auto Run Command or a Clawd-on-connect terminal; instrument the auto-run rule to confirm.
