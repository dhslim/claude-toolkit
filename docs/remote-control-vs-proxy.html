Remote Control vs the claude_proxy — the clean per-session switch solved 2026-07-02

How to use Claude Code's Remote Control (phone control) without disabling the local context-trimming proxy — one command, per session, no config changes.

TL;DR: The proxy and Remote Control (RC) can't both be active in the same session. But the proxy is just a shell function named claude. Bypass the function for one session and you get RC; use it normally and you get the proxy. Windows: run claude.exe (PowerShell) or claude in cmd. Mac / Ubuntu: run command claude.

The conflict

  • The proxy (claude_proxy.py on localhost:9999) is activated by a shell wrapper that sets ANTHROPIC_BASE_URL=http://localhost:9999, so every claude call routes through it for context-trimming (the 1M sliding-window).
  • Remote Control (Claude Code ≥ 2.1.197) enables only when ANTHROPIC_BASE_URL's host is literally Anthropic (api.anthropic.com).
  • So the moment the proxy is in the loop, RC is disabled. They are mutually exclusive per session.

What NOT to do — the failed approach (2026-07-01)

An attempt to make both work simultaneously did:
  • hosts hijack — 127.0.0.1 api.anthropic.com (so the proxy could intercept the real host), and
  • "Flavor B" — an uncommitted claude_proxy.py patch doing a DNS-over-HTTPS bypass to still reach real Anthropic despite the hosts pin.
Result: the 127.0.0.1 api.anthropic.com line collided with VMware listening on :443 with a self-signed cert → CERTIFICATE_VERIFY_FAILED: self-signed certificate → Claude Code broke on the desktop. It was fully reverted (hosts line removed + claude_proxy.py restored to committed 33b7977). Lesson: don't fuse RC and the proxy — switch between them.

The clean solution — bypass the wrapper per session

The proxy wrapper is a shell function that shadows the real claude binary and sets the proxy URL per-invocation. The real binary is on PATH (e.g. ~/.local/bin/claude / C:\Users\user\.local\bin\claude.exe), shared by all shells. Bypass the function → real binary → no ANTHROPIC_BASE_URL → real Anthropic → RC works. Nothing is edited or reverted.

OSProxy session (trimming)RC session (bypass)

Mac (zsh .zshrc function)claude in zshcommand claude
Ubuntu / Linux (bash/zsh/sh function)claudecommand claude — command is a POSIX builtin (bash/zsh/sh/dash)

Combine with normal flags: claude.exe -c / command claude -c (continue the last conversation) or … --resume "name". On Windows cmd: claude -c.

Why claude.exe works on Windows (but not Unix). The wrapper is a function named exactly claude, and PowerShell matches commands by exact name — so claude.exe never hits the function and resolves straight to the real binary on PATH (C:\Users\user\.local\bin\claude.exe). On Unix the binary has no extension, so the function and binary share the name claude and you must use command to disambiguate — claude.exe would just be command not found there. Conversely command is a POSIX builtin and does not exist in PowerShell. Hence the split: .exe on Windows, command on Unix.

Universal fallbacks (any shell)

# bypass the function without leaving the shell
command claude              # POSIX: skips function/alias, runs the real binary

# or remove the function for this session, then run normally
unset -f claude ; claude

# or call the real binary by absolute path (find it first)
which -a claude             # the entry that is NOT the function
~/.local/bin/claude

# Windows, staying in PowerShell — cleanest: just add the .exe extension
claude.exe -c
# or explicit (equivalent of `command`):
& (Get-Command claude -CommandType Application).Source -c

Why it works (mechanism)

type `claude` in the wired shell │ ▼ the `claude()` function shadows the binary set ANTHROPIC_BASE_URL=localhost:9999 → proxy → RC OFF type `command claude` (or `claude` in cmd) │ ▼ function is skipped; PATH lookup finds the REAL binary ANTHROPIC_BASE_URL unset → api.anthropic.com → RC ON

Note the wrapper function itself ends with command claude "$@" — i.e. the escape hatch is literally the same builtin the wrapper uses internally to reach the real binary.

The one caveat — RC session has no proxy

A bypass/RC session loses everything the proxy provided:
  • No context-trimming (the 1M sliding-window) — if the session grows past Anthropic's real cap you'll hit prompt is too long: … > 1000000.
  • No CLAUDE_CODE_BLOCKING_LIMIT_OVERRIDE=9000000 — the bypass session behaves like vanilla Claude Code.
Fine for phone/RC control and short sessions. For long, context-heavy work, use the normal claude (proxy) and skip RC. RC ⊕ proxy — pick per session.
