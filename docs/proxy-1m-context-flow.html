Who's Who: Claude Code → Proxy → Anthropic

A map of every actor in your setup, where each one sits in the request's journey, and exactly how the 1M context is switched on (and why it keeps reverting).

1 · The cast — who's who

Six players. The confusion is that three of them ("Claude Code", "Clawd on Desk", "the proxy") all live on your machine and all feel like "the thing I'm typing into." They're not the same.

the human

You

You type in the terminal. You never talk to Anthropic directly — you talk to Claude Code.

desktop shell

Clawd on Desk :23333

The Electron wrapper app that hosts Claude Code, draws the window, runs your hooks, and serves the permission prompt on port 23333. It's the shell around CC — not CC itself.

the agent

Claude Code (CC)

The actual agent. It turns your conversation into an HTTP request (model + messages + system + tools + headers) and sends it off. It decides which model string to send — including the [1m] tag.

your code · localhost

claude_proxy.py — "Sluice" :9999

Your local proxy. Every request from CC flows through it (because ANTHROPIC_BASE_URL=http://localhost:9999). It trims oversized context, fixes the model/header, manages the cache, then forwards upstream.

upstream · the internet

Anthropic API api.anthropic.com

The real server. Validates your auth, enforces the token cap, and requires a specific beta header to unlock the 1M window. Runs the model, streams the answer back.

the brain

The model — Opus 4.8

Lives inside Anthropic. Reads your (possibly trimmed) context and generates the reply. "200k" vs "1M" is just how big a window it's allowed to read for this request.

3 · What's actually in a request

When CC hits "send," it's a JSON body plus HTTP headers. These are the parts that matter for the 1M story:

POST /v1/messages
── headers ──────────────────────────────
authorization:    Bearer sk-ant-...        # who you are
anthropic-version: 2023-06-01             # API version
anthropic-beta:    context-1m-2025-08-07   # ← unlocks the 1M window
── body (JSON) ──────────────────────────
{
  "model": "claude-opus-4-8",            # which brain
  "messages": [ ...the whole conversation... ],
  "system": [ ...system prompt + tools... ],
  "max_tokens": 32000
}

Two different things control the 1M window — and that's the whole confusion:

KnobWhereWhat it does
modelbodyPicks the brain: claude-opus-4-8. Just the model — not the window size.
anthropic-betaheadercontext-1m-2025-08-07 is what actually flips the window from 200k → 1M. No header = 200k, period.

4 · The [1m] story — two request types, two mechanisms

The subtle part (and I'll be honest — I got this wrong twice before capturing the actual packets off the wire settled it). Claude Code asks for the 1M window two different ways, depending on the request:

RequestWhat CC sends as modelHow it signals 1MProxy
Real messages
your actual prompts — full system + tools		 claude-opus-4-8 (plain) context-1m-2025-08-07 in the anthropic-beta header ✓ passes through untouched
Session-start quota probe
a ~317-byte ping: 1 message, no system/tools		 claude-opus-4-8[1m] (suffix — a fake id) the [1m] suffix rewrites it: strips [1m] → adds the header

So your real messages were already doing it the right way (header) — the proxy leaves them alone. Only the tiny quota probe uses the hacky [1m] suffix, and that's the one thing the proxy fixes.

⚠ Why the probe must be rewritten — the 404 trap

claude-opus-4-8[1m] isn't a real model id, so Anthropic returns 404 — and Claude Code misreads that 404 as "Context limit reached — /clear to continue." Since the probe fires at session start, that 404 would surface as a broken session on your very first prompt. So _normalize_cc_1m_suffix() exists to keep that one probe alive. Real messages never hit this — they already use the header.

Why does CC do this? Two code paths: the main request path correctly translates the internal [1m] label into the header, but the lightweight quota-probe path skips that translation and ships the raw label. A CC inconsistency — the proxy is just the shim that papers over it.

The proxy code (claude_proxy.py, _normalize_cc_1m_suffix) — fires only when a model ends in [1m], i.e. only on the probe:

def _normalize_cc_1m_suffix(body, headers):
    model = body.get("model", "")
    if not model.endswith("[1m]"):     # real messages → skip, pass through
        return False
    body["model"] = model[:-4]         # probe only → strip "[1m]"
    betas.append("context-1m-2025-08-07")  # add header so the id is valid
    headers["anthropic-beta"] = ",".join(betas)
    return True

5 · The other proxy job — keeping context under the cap

Even with 1M unlocked, Anthropic rejects any request over 1,000,000 tokens. Your sessions blow past that, so the proxy trims. This is the "context chunker" part — really a sliding window.

Turn groups, not individual messages

The proxy splits the conversation into turn groups — one real user message + the assistant replies & tool round-trips that follow it. It drops whole groups from the front, which keeps tool_use/tool_result pairs intact and never breaks the "first message must be user" rule.

The anchor is a per-session watermark that only ever moves forward (a ratchet). Between shifts it doesn't move, so the byte-prefix stays identical and Anthropic's prompt cache hits ~99% — that's why most turns are fast and cheap. When context grows past the trigger, the anchor jumps forward once (a "shift"), one turn pays a cache-miss, and you're stable again.

The three numbers that govern it

ConstantDefaultMeaning
FAST_PATH950,000 BBody smaller than this can't possibly exceed the cap → forward untouched, zero overhead. ~99% of requests.
SHIFT_TRIGGER700,000 tokAbove this measured size, a shift fires and the window slides forward.
KEEP_TARGET400,000 tokWhat it slices back down to — leaves room to grow before the next shift.
MODEL_CAP1,000,000 tokAnthropic's hard ceiling. The safety re-check guarantees we never send over this.

It measures real size with Anthropic's count_tokens endpoint (a chars/4 estimate does the rough slicing; a count_tokens re-check is the safety net, because the estimate under-counts code-heavy text by up to ~2.8×).

6 · So what about the model "reverting" to 200k?

The honest, capture-checked picture:

  1. For real messages, 1M is the context-1m header — and a fresh session already includes it (confirmed on the wire: the captured request carried the header). So a new session is on 1M.
  2. The [1m] suffix only rides on the tiny quota probe (which the proxy fixes) — it is not the mechanism for your actual prompts.
  3. If you ever genuinely land on 200k, that would mean CC stopped putting context-1m in the header for real messages — a selection/persistence question on CC's side. We didn't reproduce that here, so it stays an open thread, not a confirmed bug.
