claude-toolkit · architecture

claude_proxy.py

A localhost proxy between Claude Code and api.anthropic.com. It (a) keeps long sessions under the 1M-token cap by sliding a per-session anchor forward, and (b) silently fixes a CC 2.1.145 bug where the first prompt of every session crashes with a misleading "Context limit reached" banner.

1 · Big picture

You point Claude Code at http://localhost:9999 via the ANTHROPIC_BASE_URL env var. The proxy is a FastAPI app that catches every request, may rewrite it, then forwards to Anthropic and streams the response back unchanged.

2 · The two paths

Every /v1/messages request is classified by body size. 99% of traffic — quota checks, Haiku helper calls, small Opus requests — skips the expensive token-counting work entirely.

FAST PATH

body < 950 KB

BPE guarantees tokens ≤ bytes, so a body under 950 KB cannot exceed the 1M-token cap. Forward as-is, zero overhead.

Covers ~99% of requests. ~0 ms added latency.
SLOW PATH

body ≥ 950 KB

Apply this session's sliding-window anchor (drop everything before groups[anchor]), call count_tokens for the exact size, and shift the anchor forward if over 700 K tokens.

~1% of requests. Adds one round-trip + a brief stall on shift.

3 · The sliding-window mechanic

Long sessions can't grow forever — Anthropic caps each request at 1M tokens. The proxy solves this by maintaining one anchor per session: an integer index into the list of "turn groups." Everything before groups[anchor] is dropped before forwarding.

What is a turn group?

A real user message followed by all assistant responses and tool round-trips until the next real user message. Dropping whole groups preserves three invariants Anthropic requires:

  • strict user / assistant alternation
  • every tool_use has its paired tool_result
  • the first message in the array is always a real user message

The flow

  1. Session key. Hash the first real user message text. This is stable for the life of the session and resets on /clear or /compact.
  2. Front-drop. Look up the session's current anchor in the LRU _session_watermarks dict. Drop all groups before it.
  3. Probe. Send the trimmed body to /v1/messages/count_tokens for the exact token count.
  4. Maybe shift. If the count crosses SHIFT_THRESHOLD (700 K), advance the anchor forward by SHIFT_RATIO × remaining_groups (default 0.5 = halve).
  5. Rewrite cache markers. Move cache_control: {type: "ephemeral"} to the new last cacheable block so Anthropic's prompt cache still hits.
  6. Forward. Stream Anthropic's response straight back to Claude Code.
Why halve, not slide by 1?
Between shifts, the byte prefix stays identical → Anthropic's prompt cache hits at ~99%. Each shift breaks the cache once and costs a 3–5 min slow turn, but a half-drop buys ~500 K tokens of runway before the next one. On average this works out to ~1 shift per 100–250 turns — about 1% slow-turn rate.

The count_tokens under-report

Empirically, /v1/messages/count_tokens reports a smaller number than the actual processing path uses — roughly 1.26× for mixed prose/code, higher for code-dense bodies. On 2026-04-14 we saw a 413 "Request size exceeds model context window" at count_tokens = 791,826, meaning the real cost was over 1M.

That's why SHIFT_THRESHOLD defaults to 700 K, not 900 K: 700 K × 1.3 expansion + 64 K max_tokens reservation ≈ 974 K real ≈ just under the 1M cap.

4 · The [1m] fix NEW · 2026-05-21

Claude Code 2.1.145 has a bug: on the first prompt of every session, it sends a small ~317 B probe request with model = "claude-opus-4-7[1m]" in the body — a literal, non-existent model id — instead of using the proper anthropic-beta: context-1m-2025-08-07 header alongside the bare claude-opus-4-7 id.

Anthropic returns 404 (unknown model). CC misinterprets the 404 as the context-limit error and shows the red banner "Context limit reached / /clear to continue" on the literally first prompt of a fresh session. On retry, CC silently falls back to the bare model id and the request succeeds — so the symptom is an intermittent banner that "goes away by itself."

Before — what CC sends
POST /v1/messages
anthropic-beta: prompt-caching-2024-07-31
{
  "model": "claude-opus-4-7[1m]",
  "messages": [...]
}
↓
404 Not Found  →  CC: "Context limit reached"
After — what the proxy forwards
POST /v1/messages
anthropic-beta: prompt-caching-2024-07-31,
                context-1m-2025-08-07
{
  "model": "claude-opus-4-7",
  "messages": [...]
}
↓
200 OK  →  CC: works on first try

Implementation is one helper (_normalize_cc_1m_suffix) called at the top of the request handler. It detects the [1m] suffix, strips it, and appends context-1m-2025-08-07 to the comma-separated anthropic-beta header — deduping if already present and collapsing any mixed-case duplicates.

5 · Config knobs

Env varDefaultWhat it does
CLAUDE_PROXY_FAST_BYTES 950_000 Body size below which to skip the token check entirely.
CLAUDE_PROXY_SHIFT_THRESHOLD 700_000 count_tokens value above which the sliding window shifts forward.
CLAUDE_PROXY_SHIFT_RATIO 0.5 Fraction of remaining groups to drop per shift (0.5 = halve).
CLAUDE_PROXY_QUIET unset Log only trims and errors. Otherwise verbose mode is on.
CLAUDE_PROXY_LOG_FILE proxy.log Where stdout/stderr get redirected at startup.
