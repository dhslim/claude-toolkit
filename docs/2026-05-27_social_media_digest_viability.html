Social media digest viability — what's scrapeable today

A platform-by-platform read of whether a /digest <url> skill can actually fetch useful content. Honest about the asymmetry: some platforms cooperate (RSS, public APIs, yt-dlp), others actively fight scrapers and require login or heavy machinery.

Snapshot: 2026-05-27 KST. Anti-scraping rules change frequently — revisit this when a previously-easy platform starts failing.

Tier legend

easy Public API, RSS, or anonymous web that returns the actual content. Reliable, low maintenance. Build it.
doable Works via yt-dlp / scraping anonymously. Maintenance burden — breaks every few months. Build if you actually use the platform.
painful Requires login / cookie / headless browser. Real content only after auth. Heavy deps, brittle, gray-area ToS. Build only if you really need it.
skip Either no scraping path works at all, or the value-vs-effort is so bad that copy-paste from your logged-in browser is the right answer.

Easy tier — build these first

YouTube easy

Already shipped as /youtube in this toolkit. Live-verified 2026-05-27.

Tool:
yt-dlp 2026.03.17 (12M+ PyPI downloads/month, ~2-week release cadence)
Gets:
Title, description, channel, views, likes, full transcript (manual or auto-generated)
Misses:
Real-time comments tree (yt-dlp's --write-comments is slow + flaky on popular videos)
2026 caveat:
SABR / PoToken complications. YouTube's Server-side Adaptive Bitrate started returning SABR-only formats on the web extractor in 2025, breaking the default download path. Fix: extractor-args hint + cookies from a signed-in browser. Metadata + transcript paths (what we use) are mostly unaffected — only matters if you're downloading actual video bytes.
Notes:
Works for regular videos, Shorts, live archives. UTF-8 stdout fix needed on Windows (already in our script).

Reddit easy

Tool:
Append .json to any Reddit URL → returns the full thread as JSON. No auth needed for public subs.
Gets:
Post body, every comment in the tree (with score + author + timestamp), media URLs
Misses:
NSFW / private subreddits, suspended accounts
Effort:
~30 lines Python. requests.get(url + '.json', headers={'User-Agent': 'claude-toolkit/1.0'}) + walk the JSON.

Hacker News easy

Tool:
Firebase API at hacker-news.firebaseio.com/v0/item/<id>.json
Gets:
Story, every comment by ID (recursive fetch). Sweet.
Misses:
Nothing significant — HN is fully public.
Effort:
~40 lines Python (recursive comment fetch). Zero deps beyond stdlib.

Substack / Medium / personal blogs easy

Tool:
WebFetch (already built into the assistant)
Gets:
Full article body via HTML → markdown conversion
Misses:
Paywalled Substack posts (you'd need your subscriber cookie). Medium "members only" same deal.
Notes:
For RSS-publishing blogs, prefer the RSS feed — cleaner output, batch-friendly.

Hacker News, Lobste.rs, RSS feeds easy

Tool:
feedparser Python library
Gets:
Title, body (often full-text), pub date, author
Effort:
pip install feedparser, then 10 lines.

GitHub issues, PRs, discussions, gists easy

Tool:
gh CLI (already installed if you have GitHub access) or REST API
Gets:
Title, body, every comment, labels, status
Effort:
gh issue view <url> --json title,body,comments — one line.

Bluesky easy

Live-verified 2026-05-27 against official Bluesky docs.

Tool:
Public AppView API at https://public.api.bsky.app — no auth needed for profiles, posts, feeds.
Example:
GET https://public.api.bsky.app/xrpc/app.bsky.feed.getAuthorFeed?actor=alice.bsky.social&limit=50
Gets:
Profile, author feed, post + replies, network firehose (WebSocket)
2026 caveat:
Search (app.bsky.feed.searchPosts) now requires an App Password. Profile/feed reads still fully anon.
Notes:
Cleanest of all platforms — built on the open AT Protocol. Public data is truly public. curl returns structured JSON immediately. Future-proof bet as Twitter/X locks down further.

Mastodon easy

Tool:
Per-instance REST API (e.g., https://mastodon.social/api/v1/statuses/<id>). No auth for public posts.
Gets:
Post body, reply thread (via /api/v1/statuses/<id>/context), media URLs
Notes:
Mastodon is federated, so the API host depends on the instance. URL pattern: extract the instance domain + status ID from the URL and call its API directly.

Doable tier — build when you actually use them

Twitter / X doable

Tool:
yt-dlp handles single-tweet URLs
Gets:
Tweet text, attached media, basic engagement metrics
Misses:
Thread continuation usually requires login. Replies definitely require login since X locked down public viewing.
Maintenance:
X breaks scrapers regularly. yt-dlp ships fixes within days but you'll see "extractor needs update" errors.
Alternative:
If you have an X API key (paid), use it. Otherwise yt-dlp is the only sane anon path.

TikTok doable

Tool:
yt-dlp
Gets:
Video, title (often empty), description, view count, author
Misses:
Most TikToks don't have real transcripts. Some have auto-generated subtitles if you pass --write-auto-subs but coverage is spotty (~30%).
Notes:
For audio-only digest, pipe through Whisper locally — adds ~2s/min of video but gives reliable transcript.

Vimeo, Twitch VODs, SoundCloud doable

Tool:
yt-dlp
Gets:
Media + metadata. Vimeo has captions on creator-uploaded transcripts; Twitch has none natively (use chat log for context).
Maintenance:
Low. These platforms don't actively hunt scrapers.

Spotify, Apple Podcasts doable

Tool:
WebFetch for episode page + iTunes Lookup API for show RSS
Gets:
Episode title, show notes, sometimes a chapter list
Misses:
The actual audio — Spotify locks it down hard. For digest purposes, show notes + chapter titles + an LLM summary of those is usually enough.
Notes:
Many podcasts also publish on their own RSS feed which gives you the MP3 directly. Always check the show's RSS first.

Painful tier — known unfriendly, requires login or accept partial data

Instagram painful

Live-verified 2026-05-27: anti-bot meaningfully tougher this year. Per Scrapfly: "mandatory login walls, GraphQL obfuscation, rapid IP flagging."

Tool (yt-dlp):
Officially supported. For public reels: video + caption usually works.
Tool (Python lib):
instagrapi — most actively maintained Python lib in 2026. Instaloader = free, public-only, no proxies. instascrape = simple OO wrapper.
Gets anonymously:
Public profile basics, public reel videos with captions. Carousels half-fail.
Misses anon:
Comments (login-only). Stories. Most posts past initial loads.
Anti-bot reality:
Instagram rotates GraphQL doc_id values every 2–4 weeks, breaking scrapers. Datacenter IPs banned within minutes. Detectable TLS fingerprints on naive Python requests. Needs residential or 4G mobile proxies + authenticated sessions for anything production.
If you really need it:
instagrapi + residential proxies + auth. Heavy. Plan for 1-2 hrs/month of maintenance.
Commercial bailouts:
ScrapFly, Apify, Bright Data, Lobstr.io — managed APIs that absorb the anti-bot grind.

Threads painful

Live-verified 2026-05-27: yt-dlp still has no extractor (open issue #12021, duplicate #15086, latest stable 2025.10.22, 1,839 extractors loaded, Threads not among them).

Tool (anon):
WebFetch for first-post metadata. Or DIY: Playwright headless → load page → extract embedded __RELAY_STORE__ / window.__data Relay payload → parse with jmespath. Threads is React/Relay-based and embeds JSON in inline scripts.
Gets anonymously:
First post text, author, engagement counts, view count.
Misses anon:
Thread continuation, replies, comments — all gated behind login. Threads's "teaser → continuation in reply" format is exactly what the anon view hides.
Anti-bot intensity:
Heavy. Simple requests + BeautifulSoup fails immediately (no JS execution). Datacenter IPs flagged fast. Needs residential proxy + headless browser for any depth.
Commercial bailouts:
ScrapeCreators, SociaVault, Apify "no-login" actors (some need a Session ID — those aren't anonymous; avoid them if anonymity matters). Pricing varies; commercial APIs absorb the anti-bot maintenance.
Workaround:
Many Threads creators cross-post to Instagram or X. Check the same handle there before giving up.

Facebook painful

Tool:
Graph API requires app review and user login. No useful anon path.
Notes:
Public Pages used to be partially scrapeable; Meta closed that hole. Effectively login-gated for everything meaningful.

Skip tier — copy-paste is faster than building

LinkedIn skip

Why skip:
LinkedIn is the most aggressive anti-scraper of any major platform. Multiple court cases (hiQ v. LinkedIn). Cookies expire within hours. Even with login, programmatic access trips bot detection in minutes.
Better approach:
Open the post in your browser, copy the text, paste here. Five seconds vs. days of maintaining a scraper that breaks.

Pinterest skip

Why skip:
Pinterest is primarily image-driven; the text content per pin is short and the discovery context is the value. Hard to scrape, low return.

Discord, Slack skip

Why skip:
Both require workspace/server bot tokens. Workspace-scoped data isn't "social media" in the digest sense — it's chat that already lives in your account.
If needed:
Use the platform's export feature for archival, not for one-off digest.

Recommended build order

If you want a generic /digest <url> skill, build platforms in this order:
  1. Reddit — biggest value, easiest implementation (.json trick)
  2. Hacker News — same shape, even easier (Firebase API)
  3. Substack / Medium / RSS — share WebFetch path, useful for newsletter digestion
  4. GitHub issues/PRs — gh CLI is already on disk
  5. Twitter / X — useful, but accept thread continuations need login
  6. Mastodon / Bluesky — small effort, open protocols, future-proof
  7. TikTok — only if you actually watch a lot of TikTok
  8. Stop here for most users. Below this line the ROI gets bad fast.

Architecture suggestion

Don't build a separate /reddit, /hn, /x skill for each platform. Build one /digest <url> skill that dispatches by URL pattern: 

# skill manifest just calls one Python entry point:
python digest.py "$ARGUMENTS"

# digest.py routes by domain:
match urlparse(url).netloc:
    case "youtube.com" | "youtu.be":         from fetchers import youtube      ; ...
    case "reddit.com" | "old.reddit.com":    from fetchers import reddit       ; ...
    case "news.ycombinator.com":             from fetchers import hackernews   ; ...
    case "twitter.com" | "x.com":            from fetchers import twitter      ; ...
    case s if s.endswith("substack.com"):    from fetchers import substack     ; ...
    case "instagram.com" | "threads.com":    return _ask_user_to_paste(url)
    case _:                                  from fetchers import generic_html ; ...

Each fetchers/*.py is small (one platform's quirks isolated). Adding a new platform = adding a new file. Removing a broken platform = deleting one file. No cross-contamination.

Heads-up: this landscape moves fast
Anti-scraping rules change continuously. The "easy" platforms today may close off; the "painful" ones may open up (e.g., Bluesky going mainstream gives a hopeful alternative to X). Treat this matrix as a 2026-05 snapshot, not a forever-truth. Revisit when a platform you rely on starts failing.

The "pay-the-anti-bot-tax" option

For platforms in the painful tier (Instagram, Threads, X-at-scale), there's a real "buy not build" option in 2026: managed scraping APIs. They absorb the proxy rotation, doc_id rotations, headless browser fleet, anti-bot updates — you call a stable endpoint, they handle the arms race.

ServiceStrengthsPricing modelWorth it for
ScrapFly Generic web scraping w/ anti-bot bypass, good Instagram + Threads support Credits per request Mixed platform workflows
Apify "Actor" model — many community-maintained scrapers per platform Per-actor + compute One-shot bulk jobs (e.g., scrape a creator's full history)
ScrapeCreators Unofficial Threads/IG APIs without business app or OAuth API key, tiered Production Threads/IG integration
SociaVault Threads-specific (posts, profiles, replies) API key Threads at any volume
Bright Data, Lobstr.io Big-vendor scraping infrastructure Enterprise Companies, not personal toolkits

For our specific use case ("I see a good post, I want to digest it now") none of these are worth wiring up — they're for production pipelines. The right answer for one-off Threads/IG digests remains: open in your logged-in browser, copy, paste here. Commercial APIs become attractive only when you're running this dozens of times per day.
